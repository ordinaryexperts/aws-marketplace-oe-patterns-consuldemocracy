# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

AWS Marketplace pattern that deploys [CONSUL DEMOCRACY](https://consuldemocracy.org/) (citizen participation / open government Rails app) via CloudFormation/CDK plus a Packer-built AMI. Components:

1. **Custom AMI** — Packer, Ubuntu 22.04 (`packer/ami.json` + `packer/ubuntu_2204_appinstall.sh`). The provisioning script clones `consul/installer` (Ansible-style) and pins the upstream version with `git checkout 2.2.0` — the version is **not** in a parseable `*_VERSION=` env var.
2. **CDK stack** (Python) — `cdk/consuldemocracy/consuldemocracy_stack.py`. Uses constructs from `oe-patterns-cdk-common`.
3. **Marketplace listing** — `plf_config.yaml` (legacy PLF spreadsheet workflow; this repo has not been migrated to `marketplace_config.yaml` + the Catalog API).

Infrastructure deployed: VPC, Aurora PostgreSQL, S3 assets bucket, SES (Easy DKIM), ALB + ACM, ASG (no Graviton, `t3.xlarge` default), Route53. **No Redis, no OpenSearch** — simpler than Mastodon.

## Status: legacy (per `patterns-dashboard/patterns.yml`)

Last MP release `1.0.1` on 2024-10-21. FOSS upstream is at 2.5.0 vs. shipped 2.2.0 → significant drift. Several conventions in this repo are behind the current pattern fleet — see "Modernization gaps" below before starting an upgrade.

## Common Commands

`Makefile` is intentionally minimal — it only defines `deploy` and `update-common`, then `-include common.mk` from `aws-marketplace-utilities`. All other targets (`synth`, `lint`, `test-main`, `ami-ec2-build`, `publish`, `gen-plf`, `plf`, `clean-*`, etc.) come from `common.mk`. Do **not** add targets to `common.mk` here — that file is managed in `aws-marketplace-utilities` and pulled in via `make update-common` (currently pinned to `1.5.1`).

Common targets:
- `make build` / `make rebuild` — devenv Docker image
- `make synth` / `make synth-to-file` / `make diff` / `make deploy` / `make destroy`
- `make ami-ec2-build TEMPLATE_VERSION=<v>` — build AMI via Packer
- `make lint`
- `make publish TEMPLATE_VERSION=<v>` — upload `dist/template.yaml` to the patterns S3 bucket
- `make gen-plf AMI_ID=<id> TEMPLATE_VERSION=<v>` / `make plf …` — legacy PLF workflow

Everything runs in the `devenv` Docker container — never run CDK/Packer on the host. AWS profiles are passed via env (e.g. `AWS_PROFILE=oe-patterns-dev make deploy`); `~/.aws` is mounted into the container.

There are **no taskcat tests** in this repo (`test/main-test/.taskcat.yml` does not exist) and **no playwright integration tests** (`test/integration/` does not exist). `make test-main` will not work until those are added.

## Architecture

`cdk/consuldemocracy/consuldemocracy_stack.py` composes these constructs from `oe-patterns-cdk-common`:

- `Vpc` — create-or-use-existing
- `Dns` — Route53 hosted zone integration
- `AssetsBucket` — S3 + CloudFront for user content
- `Ses` — domain identity + Easy DKIM (the SES SMTP password is generated by a Lambda in cdk-common; the instance pulls credentials from Secrets Manager at boot)
- `DbSecret` + `AuroraPostgresql` (database name `consul_production`)
- `Asg` — uses `default_instance_type="t3.xlarge"`, `use_graviton=False`. Reads `cdk/consuldemocracy/user_data.sh` and substitutes `${...}` variables (CFN substitution syntax) at synth time
- `Alb` — health check path `/elb-check`

CFN parameters specific to this pattern (everything else comes from the construct `metadata_parameter_group()` calls):
- `AdminEmail` — initial admin login (defaults to `admin@<DnsHostname>`)
- `DelayedJobCount` — 1-10, number of delayed_job worker processes

The AMI ID is hardcoded in two places in `consuldemocracy_stack.py`: the `AMI_ID=` constant and the matching entry in the `generated_ami_ids["us-east-1"]` map. Other regions in that map are placeholders (`ami-XXXXX...`); multi-region copy via `ami-ec2-copy` would populate them, but the modern Marketplace Catalog API replicates regions automatically.

User data (`cdk/consuldemocracy/user_data.sh`) pulls DB and instance credentials from Secrets Manager (DB secret + a Lambda-populated `<StackName>/instance/credentials` secret with `admin_password`, `secret_key_base`, `smtp_password`, `access_key_id`, `secret_access_key`), writes Rails config, and starts the app.

## Modernization gaps (read before upgrading)

This repo predates several conventions documented in `aws-marketplace-utilities/UPGRADE.md`. A version upgrade likely needs to address most of these in the same release:

| Area | Current | Modern (per UPGRADE.md) |
|---|---|---|
| Devenv image | `:2.5.3` (`Dockerfile`) | `:2.8.3+` (fixes hardcoded template bucket, broken logo validate, PEP 668) |
| `oe-patterns-cdk-common` | `3.20.0` | `4.5.0+` (required for `ami_id_param_name_suffix`) |
| `aws-cdk-lib` | `2.120.0` | `2.225.0+` |
| Ubuntu | 22.04 (`ubuntu_2204_appinstall.sh`) | 24.04 (`ubuntu_2404_appinstall.sh`) |
| Marketplace config | `plf_config.yaml` (deprecated PLF) | `marketplace_config.yaml` (Catalog API) |
| AMI parameter name | bare `AsgAmiId` | versioned suffix, e.g. `AsgAmiIdv110` |
| FOSS version pin | `git checkout 2.2.0` (free text) | `*_VERSION=` env var so the dashboard can auto-derive `mp_foss_version` |
| Tests | none | `test/main-test/.taskcat.yml` + `test/integration/` (playwright) |
| Pip install | plain `requirements.txt` (no `setup.py`) | either convention is supported; current is fine |
| `Makefile deploy` parameters | hardcoded `VpcId` / `VpcPrivateSubnet*Id` / `VpcPublicSubnet*Id` pointing at a specific dev VPC | drop them so the stack creates a fresh VPC (per UPGRADE.md note about "VPC parameter hygiene") |

`update-common` pin is `1.5.1`; bumping the devenv image likely also wants a newer `common.mk` (re-run `make update-common` against the latest utilities tag).

The dashboard manifest (`patterns-dashboard/patterns.yml`) flags this pattern with `mp_foss_version_var: ''` — once the packer script is converted to use `CONSUL_DEMOCRACY_VERSION=…`, set `mp_foss_version_var: CONSUL_DEMOCRACY_VERSION` so refreshes auto-derive the FOSS version. Until then, set `mp_foss_version_override` on each release.

## Upgrade Workflow

Follow `aws-marketplace-utilities/UPGRADE.md` end-to-end. Pattern-specific notes for Consul Democracy:

- **Phase 1.1** — current upstream version lives in the `git checkout 2.2.0` line (line ~149 of `packer/ubuntu_2204_appinstall.sh`), not a `*_VERSION=` variable.
- **Phase 1.2** — upstream releases: `gh release list --repo consuldemocracy/consuldemocracy`. The repo also publishes its own ansible installer at `consul/installer` — check whether that needs a matching update.
- **Phase 2.3.1** — introduce the versioned AMI parameter convention (`AsgAmiIdvXXX`). The pattern currently has bare `AsgAmiId`.
- **Phase 6** — this repo has no `marketplace_config.yaml`. The legacy PLF workflow (`make gen-plf`/`make plf`) still works against `plf_config.yaml`, but moving to the Catalog API means writing `marketplace_config.yaml` from scratch. The product UUID is `prod-paiemurjqun6o` (from `patterns-dashboard/patterns.yml`); the AWS Marketplace product title currently uses the older "Ordinary Experts CONSUL DEMOCRACY Pattern" wording — see UPGRADE.md "Brand alignment check" and "Updating product metadata" for the rebrand to "Consul Democracy on AWS by FOSSonCloud".
- **Phase 8** — there is no companion `terraform-aws-marketplace-oe-patterns-consuldemocracy` module; skip that phase or create one.
